Cuenta

The blueprint: one app, one database, one email service, and one invoice layout used three ways.

How it works, in plain language

Cuenta is one Next.js app on Vercel. Everything Eileen records lives in one Postgres database on Neon. When she taps Save, Create invoice or Mark paid, the page calls one of the app's own API routes, which checks her PIN session, writes to the database, and logs one line. Every invoice is a snapshot, so nothing that changes later can rewrite it.

One invoice layout does three jobs: the screen, Print, and the PDF. For the PDF, the server opens a hidden print page in a headless Chrome with a 60-second pass for that one invoice, and saves it. Resend emails the PDF. All dates are worked out in Pacific time by one helper.

Where it runs

Local: Node (the current LTS Vercel supports) and a Neon database. Local dev uses the Neon dev branch; production uses main (set up in 5-build, after test invoices landed in production). Schema changes are migrated to both. cp .env.example .env.local · npm install · npm run db:migrate · npm run db:seed · npm run dev.

Deployed: production on Vercel, connected to the public GitHub repo, is the judge URL. Headless Chrome loads APP_URL, which must be the production domain, since Deployment Protection on preview URLs would block it.

Demo video: the judge path on the production URL: Count for Corazon Cocina → Deliver → Invoice: Print, then Email (To is the mock cafe's delivered@resend.dev) → Ledger. Then the send shows as Delivered in the Resend dashboard with Invoice-[number].pdf attached, and the matching message ID in Vercel's function logs. No personal email address appears on screen.

Submission: a short demo video and a public GitHub repository are both required. The deployed URL is an addition, not a substitute.

Components

PIN Gate

prd.md › PIN Gate

  • POST /api/session compares to APP_PIN in constant time and sets the cuenta_session cookie (HMAC-signed exp, httpOnly, Secure, Lax, 30 days).
  • proxy.ts guards everything except /pin, /api/session, /print/*, /health, /help (the How it works page, which holds no data) and static assets. Pages redirect to the PIN; the API returns 401.
  • Attempt limiting (lib/pin-limit.ts, table pin_attempts): every wrong PIN adds a fail row with the client IP. 5 fails from one IP within 15 minutes add a lock row for that IP; 20 fails from anywhere add a global lock (IP null). Any lock younger than 15 minutes for the caller's IP, or a global one, returns 429 "Too many tries. Wait 15 minutes." before the PIN is compared. Attempts during a lock aren't counted, so they don't extend it. The IP comes from x-forwarded-for.
  • Each failure logs {route, outcome, ip, ts}, never the digits.

app/pin/page.tsx · app/api/session/route.ts · lib/session.ts · lib/pin-limit.ts · proxy.ts

Count Screen

prd.md › Count

  • Shows the menu (every active product, the same for every cafe). Steppers start blank; Save is disabled while every row is blank. POST /api/counts sends only the entered rows, then the page refreshes, clears the steppers and shows "Saved" for 2 seconds. counts rows are only ever added, so untouched products keep their old count.
  • The last cafe is kept in the cuenta_last_count_cafe cookie. A shared dirty flag drives the prompt on cafe switch and on nav.
  • Past counts (added in 5-build, built in slice 8): a link under the picker opens count/past/page.tsx?cafe=, which reads every count row for that cafe, groups them by counted_on (newest first, then by menu order), and renders them read-only.

count/page.tsx · count/past/page.tsx · CountForm.tsx · Stepper.tsx · nav/unsaved.ts · queries/counts.ts

Deliver (New and Edit)

prd.md › Deliver (New Delivery and Edit)

  • One DeliveryForm for both. One line per menu product (the same for every cafe): name, editable unit price, blank qty, line total, grey count. Special order lines (description, unit price, qty) included.
  • Create sends POST /api/invoices; Edit sends PUT /api/invoices/[id]. Create invoice is disabled until a line has qty above 0.
  • A numberTouched flag stops the suggestion following the date or cafe. A duplicate returns 409 {usedOn, cafeName}: “Already used on Oct 3 for Corazon SB”.
  • Edit loads the saved copy (prices and descriptions), never the current products.
  • Cafe switch on Edit: locked (decided in slice 7). Switching would re-snapshot the cafe and reload its prices mid-edit; PUT answers 400 if customerId differs. Void and recreate instead.
  • Split (slice 7): useDeliveryLines.ts holds line state, prices, special orders and totals; SpecialOrderRow.tsx sits next to LineRow.tsx; DeliveryForm keeps the header, the mode (new or edit) and submit.

deliver/page.tsx · invoices/[id]/edit/page.tsx · DeliveryForm.tsx · useDeliveryLines.ts · LineRow.tsx · SpecialOrderRow.tsx · api/invoices · lib/api/duplicate-number.ts

Invoice Document: the kernel

prd.md › Invoice · Look and Feel

  • A pure component that renders a saved invoice as the Canva form. Used only by the Invoice screen and the print route.
  • Its CSS module plus print.css are the only invoice-shaped styles in the codebase. Lines with qty above 0 render in their saved order; the logo renders when set, otherwise its space stays empty.
  • Type: Limelight INVOICE · body "Times New Roman", Tinos, "TeX Gyre Termes", Times, serif. Tinos (self-hosted with next/font) is metric-compatible with Times New Roman; serverless Chromium has no system fonts, so the PDF renders in Tinos and breaks lines exactly where Eileen's Windows print does · PNG wordmark, footer title and headers from public/invoice/, exported from Canva and trimmed to their ink.
  • Layout unit: every element sits at its PDF-point coordinates from her form (612 × 792 Letter), scaled from the page width (--pt), so screen, print and PDF share one coordinate system.
  • Footer identity from BUSINESS_* env vars: placeholders in the repo, real values only in production.
  • MAX_LINES_ONE_PAGE, measured in Block 3 at 8: the form's 36pt spacing for up to 5 lines, tightening evenly to 22pt. Above it: “Too many lines for one page”, and PDF/email return 422. It never overflows silently.

Invoice Screen

prd.md › Invoice

  • Shows <InvoiceDocument>, the grey status line, and Print · Download PDF · Send email / Send again · Edit · Void (one confirm, then POST …/void).
  • Email draft: the page builds it on the server (buildInvoiceEmail, the saved cafe_email, sendButtonLabel) and hands it to the Email pop-up, so To is filled the moment the pop-up opens.
  • Navigation: the bottom nav stays; a "← Back to Ledger" link sits at the top.
  • Download PDF: the route answers with Content-Disposition: attachment. The button fetches it in the background and saves the file, so the tab never navigates to the PDF, and a failure can still show the quiet one-line message.
  • Sheets (components/ui/Sheet.tsx): an open sheet pushes one history entry (marked cuentaSheet), so the phone's back button closes it. Cancel, a tap outside, Discard or a successful send close it through useSheetClose(), which steps back off that entry before running the action, so a follow-up navigation is never undone.

invoices/[id]/page.tsx · InvoiceActions.tsx · EmailSheet.tsx · ui/Sheet.tsx · lib/email-status.ts

Print Route

prd.md › Email Invoice · Invoice

  • /print/invoice/[id]?t=: the token is an HMAC(id, exp) with PRINT_TOKEN_SECRET, valid 60 s and scoped to one invoice.
  • A bad, expired or wrong-invoice token returns 404. It never reads the PIN cookie, never logs the token, and sends noindex.
  • Used only by the renderer. Eileen's Print button calls window.print() on the Invoice screen.

PDF Renderer

Spike 1 · learner-written pass criteria

Flow
  • Mint a token, launch Chromium, open the print URL, wait for load, document.fonts.ready and every image to decode, then pdf({format:'Letter', printBackground:true, preferCSSPageSize:true}).
  • Used by …/pdf (Download, served as an attachment) and …/email. maxDuration is 60 s on both; Spike 1 measured a cold render at about 6 s server-side.
  • Bundling: serverExternalPackages covers @sparticuz/chromium and puppeteer-core; outputFileTracingIncludes adds the Chromium bin/ to the PDF and email routes. Route keys are globs: /api/invoices/*/pdf, not [id].
Pass / fallback
  • Release within the last 6 months; fits Hobby's size limit.
  • Under 10 s cold, under 3 s warm. Limelight and the PNGs render correctly.
  • If it fails after 60 min: a hosted renderer on the same URL. Never a second layout.

Email Sender

prd.md › Email Invoice

  • Email pop-up (EmailSheet), given an EmailDraft by the Invoice page, with no separate preview request (the old email-preview route was removed in 5-build). To is the snapshot cafe_email (editable for this send only), so she never types the recipient: one tap on Send email. No email saved: autofocus in To, "No email saved for this invoice. Type one to send.", and Send email disabled until the address is valid.
  • Preview: the subject, the body collapsed to its first two non-empty lines with "Show full email", and the attachment line.
  • Buttons: Cancel and Send email (black), in Sheet.module.css's .actions row, which is position: sticky at the sheet's bottom so they never scroll away. After a send: "Send again" with "Last sent …" above.
  • POST …/email {to}: build the template (subject La Condesa Baking Company Invoice ${number}, attachment Invoice-${number}.pdf), render the PDF, then resend.emails.send({from, to, replyTo, subject, text, attachments}).
  • Success: email_sent_at + message ID, and the failure flag clears. Any failure (PDF, network or Resend): email_last_failed_at + 502, never clearing an earlier email_sent_at; the pop-up stays open with the failure line and Try again. Resend's reason goes to the log only, with addresses scrubbed.
  • Status line (lib/email-status.ts): “Last sent Oct 18, 9:14am” · “Last sent Oct 18, 9:14am · last try failed” · “Not sent” (only if no send ever succeeded) · nothing if never attempted. The stamp never lies.
  • The template lives in lib/email/invoice-email.ts until Handoff.
  • Sender: domain verification isn't a gate (learner decision in 5-build). Until lacondesabakingcompany.com verifies, EMAIL_FROM is Resend's onboarding sender, which only delivers to the account owner's inbox. Then setting EMAIL_FROM/EMAIL_REPLY_TO in Vercel and redeploying makes the switch, with no code change (checklist slice 8 polish, before submission). DNS records go in at her registrar and are merged into any existing SPF record.
  • Onboarding sender: while EMAIL_FROM is onboarding@resend.dev, Resend delivers only to the Resend account owner's address and to its test addresses, and refuses every other recipient with a 403.
  • Mock cafes bill to delivered@resend.dev (Resend's test inbox), set in seed/mock-data.ts. Sends really go through and show “delivered” in Resend, and no personal address is ever on screen (learner decision before the demo video).

Ledger

prd.md › Ledger

  • queries/ledger.ts returns totalCents (summed from the lines), dueOn (+30), overdueDays (vs todayPacific()) and the status.
  • ledger-stats.ts: Open, Outstanding, This month, excluding void. Filtered with ?cafe=.
  • Sorted by invoice_date desc, then created_at desc.
  • PaymentSheet: Mark paid sends POST …/payment {paidOn, reference}; Mark unpaid is one confirm, then DELETE …/payment. Void is POST …/void; void rows have no payment action.
  • Email label: emailLabel() gives the envelope plus “Emailed Oct 17” in grey, with “Emailed Oct 17, 8:12pm” as the title (hover) and aria-label. If no send succeeded and one failed, it reads “Not sent”. No icon ever appears without words.

Customers Screen

prd.md › Customers (read-only)

  • Shows the menu once at the top (every product and price, shared by every cafe), then each cafe's details and logo, read-only.
  • No admin screens yet: products and cafes change only through the seed. Editing comes at Block 8.

Logging & Health

prd.md › Operational Requirements

  • with-route.ts wraps every API handler and logs one JSON line: {ts, route, outcome, ms, invoiceNumber?, cafe?, messageId?, error?}.
  • Never logged: emails, addresses, phones, bodies, the PIN, tokens, env values.
  • No indexing: next.config.ts sends X-Robots-Tag: noindex, nofollow on every response, static files included (the proxy skips those), and public/robots.txt disallows everything.
  • /health runs select 1 and returns {ok, db: 'up'|'down', version}. The client fetch wrapper shows one-line errors and logs them to the console.

Dates & Money

  • TZ='America/Los_Angeles'. todayPacific() is the only source of "today". Nothing reads the browser's clock for a date.
  • Block 1 check: an invoice created at 5:30 pm Pacific gets today's date and today's number.
  • Integer cents everywhere. suggestNumber(1, '2026-10-17') returns 110172026.

Data model

Reference (seeded)
  • customers: code (unique), name, phone, address_lines, billing_email?, logo_path? (mock: a generated placeholder), sort
  • products: slug (unique, stable), name, price_cents, active, sort (menu order, added in 5-build). Open-ended count; Block 1 sixth-product check.
  • One menu for every cafe (corrected in 5-build): every active product, in sort order, is on every cafe's Count and Deliver at the one price, via listProducts(). The old per-cafe table standing_items was removed by migration 0002_one_menu.
Records
  • counts: rows only added: customer, product, qty, counted_on (date)
  • invoices: number (unique text), invoice_date, cafe snapshot, voided_at, paid_on, paid_reference, email_sent_at, email_message_id, email_last_failed_at
  • invoice_lines: product_id? (null = special order), description, unit_price_cents, qty ≥ 1, position
  • pin_attempts: kind (fail or lock), ip? (null on a global lock), at. Added in 5-build

Due date and totals are calculated, never stored. Blank menu rows are never saved, so an invoice holds only what was delivered.

Failure modes

BreaksShe sees
Chromium too big or slow on VercelSpike 1 decides → hosted renderer. PDF/Email show a one-line failure; Print always works.
Resend failsThe invoice is already saved · "Couldn't send…" + Try again · "Not sent", or "Last sent … · last try failed" after an earlier success · never "Last sent" for a send that failed.
Neon cold start or outageA one-line error, never blank · /health tells them apart · warm it before the demo.
Duplicate number raceThe unique index → "Already used on…".
Late-evening datePrevented by todayPacific(); Block 1 check.
